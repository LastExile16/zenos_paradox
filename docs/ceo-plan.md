# CEO Plan: Zeno's Paradox — An Interactive Journey into Infinity
Generated by /plan-ceo-review on 2026-10-10
Branch: main | Mode: SCOPE EXPANSION
Repo: zenos_paradox (greenfield; sole artifact is design.md)

## Vision

### 10x Check
Three moves take this from "a scale explorer with a philosophy footnote" to
something people remember:

1. **The user's real hand, not a modeled one.** Live thumb/index tracking via
   MediaPipe Hands drives the gap. The user narrows *their own* gap and watches
   the universe inside it respond. Every other scale journey shows you a picture
   of a thing; this one shows you yourself.
2. **The journey runs both ways.** Zeno's dichotomy is symmetric — you can never
   traverse a distance either, because you must first cover half. Extending the
   same log scale upward (room, building, city, Earth, cosmos) doubles content
   for near-zero architectural cost and turns a one-way zoom into a position in
   the universe.
3. **The halving counter as emotional spine.** A persistent `n` climbing with
   every halving converts an interaction into an argument.

### Platonic Ideal
You open it on your phone and see your own hand on the screen, live, thumb and
index apart. You pinch them together. The world inside the gap magnifies.
Fingerprint ridges rise around you like canyon walls. You keep going and the
walls become a translucent, breathing cell membrane. Then bonds. Then electron
fog, and the readout says `53 pm` — the Bohr radius, the electron cloud's
edge. You have halved thirty times. There is
still a gap. The experience lets you sit with that — and tells you, quietly,
that there always will be. You reverse, fly back up through every layer, and
your hand is exactly where you left it.

No UI but the gap and a number. No instructions, because you already know how
to make a gap smaller. Works with a keyboard, with a screen reader, and in
English first with Kurdish, Arabic, Chinese, and Japanese following. It is the
paradox, not a website about the paradox.

## Architectural Commitment (from 0C-bis)

**Approach A — "Gap-frame invariant"** was selected over two alternatives.

The **gap**, not the hand, is the invariant that survives all ~27 halvings.
The hand is the prologue of the journey, not its frame. The two fingertip
surfaces become the two walls of every stage, and the camera always flies
between them. A single contour/line visual language unifies all stages so a
fingerprint ridge, a cell membrane, a chemical bond, and an orbital contour are
the same kind of mark at different zoom.

Rejected alternatives:
- **B) Staged rooms, continuous number** — fits the existing phase plan and is
  lower risk, but its designed seams silently break the Section 6 continuity
  promise, and heterogeneous styles fight the demanded cross-stage coherence.
- **C) Zeno-first, number is protagonist** — the only version where the paradox
  is the product rather than a footnote, and cheapest to make excellent, but it
  de-emphasizes the hand, which is the most approachable, most instantly
  readable hook. Retained as the fallback if budget collapses.

- Bidirectional journey: cosmic scale above the hand, atoms and the Zeno void

## Resolved Architecture Decisions (from the 11-section deep review)

- **Input arbitration:** single write path recording the source of each change;
  user input overrides a deep link (1A).
- **Wall contract:** an explicit interface every stage implements — two facing
  surfaces at a given gap width plus camera framing — and it is documented
  in-repo as the extension contract for adding stages (1B, 10A).
- **Asset loading:** predictive preload of adjacent stages by direction and
  velocity; a designed hold (camera slows, walls dissolve) instead of a
  spinner if the user outruns the preload (1C).
- **Error rescue:** restore WebGL context, then fall through to the SVG/DOM
  fallback; every stage defines a cheap degraded tier so a failed asset never
  stalls the journey; deep links clamp and prefer `n`; i18n keys fall back to
  English; display uses pure scientific notation below 1 mm and never renders
  `NaN` or `0 mm` for a nonzero gap (Section 2).
- **Security/ops:** full privacy posture for the camera (on-device note in the
  prompt, stream stopped on tab hide and stage exit, live indicator); MediaPipe
  model pinned and vendored into the bundle; URL params number-coerced at the
  boundary (3A/3B/3C, 9B).
- **Interaction:** mid-transition input retargets the in-flight animation;
  one interpolator chases the model value with haptic ticks keyed to crossed
  orders of magnitude, not taps; separate visualizable vs. mathematical bounds
  so the slider floor never clamps the Halve button and the void stays
  reachable; pause rendering and tracking on visibilitychange (Section 4).
- **Tests:** property tests on the number model (halve/double identity,
  `d_n = d_0/2^n`, never-reaching-zero, per-locale formatting table) plus a
  named runner wired into CI (6A/6B).
- **Performance:** explicit degradation ladder — cap DPR, then shadow/lighting
  tiers, then geometry LOD, then reduce MediaPipe inference cadence, never
  frame rate first; inference decoupled from render at 15-30fps with prediction
  between samples (7A/7B).
- **Observability:** named error sink for the ten error classes (redacted
  payloads only), FPS sampling plus stage-reach events, and a `?debug=1`
  overlay showing gapWidth / n / scaleStage / FPS / active input source
  (8A/8B/8C).
- **Deployment:** content-hashed immutable asset URLs with the prior release
  retained so rollback is one config switch (9A).
- **UX:** two-pane desktop (scene ~62% / panel ~38%), one overlay language on
  mobile; designed first paint with the hand appearing as early as possible;
  keyboard and slider are first-class input paths, not fallbacks, with a text
  alternative authored per stage (11A/11B/11C).
- **Debt (tracked):** the modeled 3D hand exists only to cover camera denial
  and is a second hand to author, animate, and keep coherent with the live one
  (10B).

## Key Corrections to design.md
0. **Localization premise is wrong.** The doc states "Japanese and English are
   supported from the beginning." Corrected per the user: **English is the
   primary language**; v1 ships English-only with the full i18n plumbing
   already in place (externalized strings, locale-aware formatter, RTL-aware
   layout using logical CSS properties). Then Kurdish Sorani, Kurdish Kurmanji,
   Arabic, Chinese, and Japanese land as string contributions with no layout
   rework. Kurdish Sorani and Arabic are RTL, so mirroring the HUD, slider, and
   side panel must be built once, up front, not retrofitted.
1. **The hand cannot be the frame for a journey to atoms.** 10 mm to 0.1 nm is
   8 orders of magnitude, ~27 halvings. Around the cell stage there is no hand
   left. The doc files this under "transitions"; it is the central design
   problem of the whole experience. Resolved by Approach A: the gap is the
   invariant frame, the hand is Stage 1 content only.
2. **Floating-point precision is not the risk the doc thinks it is.** In a JS
   float64, 27 halvings (or ~109, to the Planck length from a 10 mm origin) is trivial
   magnitude-wise and retains ~15 significant digits throughout. The real
   precision problems are display rounding and unit selection. Do not engineer
   around a phantom.
3. **The atom-stage representation is an architecture decision, not a Phase 3
   detail.** Bohr shells, electron probability density (isosurfaces/volumetric
   rendering), and quantum-cloud-with-collapse are wildly different in cost and
   in rendering budget. Decide in the plan; the probability-density path
   changes the mobile performance story.
4. **Phase 2 then Phase 3 is the wrong order.** Scale navigation cannot be
   validated against grey boxes. Build one transition end-to-end at full
   fidelity (hand to fingerprint), prove the transition language, then
   replicate the pattern across the remaining stages.

### Stage flow (what the user witnesses in order)
```
  Hand ──→ Fingerprint ──→ Cell ──→ Molecule ──→ Atom ──→ Void
  d≈10mm   d≈0.5mm       d≈5µm    d≈0.3nm     d≈53pm    d→0
  n=0      n≈14          n≈21     n≈28        n≈34      n→∞
  (content)(surface)    (membrane)(bond)   (cloud)   (counter)
```
Every stage is the *same* gap with the *same* two walls; only the content
between them and the camera distance change. That is the invariant.

### Per-stage primary/secondary/tertiary

|---|---|---|---|

| Molecule | bond + atoms | molecule size range | "Which molecule?" |
| Atom | electron cloud | Bohr radius (53 pm) | "What is probability density?" |
| Void | counter `n` + the line | — | "Why never zero?" |

### Pass 4: AI Slop Risk — Rating 8/10

Classifier: **HYBRID** (art-led 3D scene + minimal UI panel = app-like with
marketing-level visual impact). Hard-rejection patterns checked:
- No 3-column card grid (the UI is a single scene + a panel — not cards).
- No hero with weak brand (brand = the scientific instrument identity; the gap IS the brand).

### Pass 6: Responsive & Accessibility — Rating 7/10

line of a11y tokens (contrast ratio, focus indicator, ARIA roles).
